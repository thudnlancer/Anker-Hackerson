# 离线试验场首轮对比分析（epoch-replay v1）

数据：AWS 采集的 5 个滑动 168h epoch（2026-10-10 ~ 10-25，overlap=True）× 3 站点，
共 60 组完整 672-tick 回放（去重后）。判定量：settled cost vs 同物理自用基线。

## 站点基线特性（每 epoch 自用成本均值）

| 站点 | 基线 EUR | 特性 |
|---|---|---|
| site_1 | **-9.03** | 净收益方（PV 富余，自用还赚钱），百分比指标会失真 |
| site_2 | **≈0.00** | 净平衡，百分比无意义（分母≈0） |
| site_3 | **+20.53** | 净付费方（负载重），百分比最干净 |

## 主结果：节省额 EUR/epoch（均值±标准差，跨 epoch-site）

| 策略 | persistence（下界） | v16（现实点） | perfect（上界） |
|---|---|---|---|
| **MILP** | 3.58 ± 3.00 (15 run) | **4.17 ± 3.40 (10 run)** | 5.87 ± 4.01 (11 run) |
| **梯度** | 1.01 ± 3.11 | 0.02 ± 2.83 | 1.58 ± 6.13 |

## 关键结论

1. **预测质量排序成立：persistence < v16 < perfect**（仅对 MILP）。
   v16 比 persistence 多省 +0.6 EUR/epoch（+17%），吃到了 persistence→perfect
   改进空间（2.29 EUR）的约 **26%**。
2. **梯度策略全面显著弱于 MILP**，且预测越准它越不会利用
   （perfect 下波动极大、v16 下≈0）。其定位应限定为「无求解器环境的兜底」。
3. **site_3（负载重站）是预测价值的试金石**：persistence 下 MILP 在
   epoch_00/01 反而**亏** 0.6~0.7 EUR/epoch（追了不存在的价差 + 退化成本），
   perfect 才转正（+0.3~2.1）。v16 未能挽回这两个 epoch 的亏损。
4. MILP 非最优求解率：persistence 199/10080 tick（2%）、v16 148/6720（2.2%），
   均为 5s 时限 incumbent，风险可控。

## 重要 caveat（不粉饰）

- **终端 SOC 失真**：各 run 末态 SOC 分布 0%~100%，settled cost 未对末态储能
  计价。末态更满的 run 相当于「账面吃亏、库里有钱」。后续应按统一终值单价
  折算末态 SOC 后再比较。
- **epoch 间重叠 ~78%**：5 个滑窗不是独立样本，标准差仅作离散度参考。
- site_2 基线≈0，其 saving_percent 一律无效；全表一律用 EUR 绝对值比较。
- v16 冻结元数据 development_pass=false / formal_acceptance=false，
  上述数字不构成模型的正式验收。

## 下一步建议

1. 终值修正后重算对比（消除 SOC 失真）。
2. 数据量已够切**不重叠** epoch（AWS 已存 50+ 天连续数据），重建后复跑核心组合。
3. v16 在 site_3 的失效点单独做误差解剖（预测残差 vs 实际负载分布）。
