# SOP 复核与实现基线

> 这是早期 SOP 对齐记录；第 3 节的“尚未完成”是当时状态，不可替代当前在线验收结论。当前状态见 [在线流程里程碑](../milestones/ONLINE_FLOW_MILESTONE.md)。

## 1. 已确认的比赛事实

### 时间与循环

- `device_time` 是加速后的设备时钟，策略判断当前小时、当前电价档位和昼夜状态只能使用它或电价 API 的当前档位。
- 本机/HA 服务器墙钟只用于保持约 5 秒真实时间轮询、请求超时和传输新鲜度检查，不能用于判断设备小时。
- 官方示例倍率为 `x180`：一个设备小时约对应 20 秒真实时间；一个 5 秒 tick 约覆盖 15 设备分钟。策略必须每轮重新读取设备时间和 API 当前数据。
- 价格按小时分档，今日/明日 API 是完整时间窗口；不能将单日数组按索引回绕到另一日。

### 数据边界

- 设备实时状态和控制必须经 HA；不能直连 Modbus 端口获取设备数据或下发控制。
- 电价和天气是模拟器公开信息 API，可直接请求；电价三站共享，天气按 `site=1/2/3` 区分。
- 天气 API 提供逐小时辐照度、云量、温度；天气与对应站点 PV 同源同期，辐照度是最重要的 PV 信号。
- 比赛窗口启动后，`/api/contest/history?site=N` 提供窗口前 7 天逐小时真实历史，字段与训练数据特征口径一致。赛前 404 不代表接口永久不存在。
- 100 站点训练集用于离线泛化和策略 replay，不是三台比赛设备的身份历史。

### 控制语义

- `self_consumption` 是默认自发自用模式；策略控制使用 `third_party_control`。
- `charge` 的 `power_control` 是电池充电功率。
- `discharge` 的 `power_control` 是并网点输出目标，不是电池放电功率。电池实际放电量由光伏余量和负载共同决定。
- 切换第三方模式后应等待约 1 秒，再设置方向和功率；写入约 5 秒后在下一个 tick 生效。
- `hold` 不能被静默编码为零充电或零放电；正式执行应切回 `self_consumption` 或采用经过回读验证的安全无动作方案。

### 物理与评分

- 三台设备统一为 14 kWh、充放电额定功率 5 kW、光伏装机 5 kW。
- 比赛 SOC 空间固定为 `0%~100%`，充电上限、放电下限和备用预留不可修改。
- SOP 口径的约 5% 损耗计入充电侧；不能在放电侧再次重复扣除同一效率损失。
- 卖电价可能为负，代表向电网送电会产生损失；买电价恒为正，不存在负买电价补贴。
- 排名使用三站合并的 `saving_settled_percent = ΣΔR_settled / ΣK`，不是三站百分比的简单平均。
- `ΔR_settled` 包含比赛结束时电池库存按整场平均买电价计算的结算价值；`saving_percent` 仅为已实现收益参考值。
- 模拟赛可反复运行；正式赛每个纪元只能启动一次，必须先充分完成模拟赛和链路自检。

## 2. 已修正的实现

- API-first shadow 现在从 API 时间戳推导无时区后缀 `device_time` 的对齐坐标，不使用墙钟决定设备小时。
- shadow 默认使用比赛完整 `0%~100%` SOC 边界；内部保守保底只能显式作为实验参数。
- 物理模型默认采用充电侧 0.95 效率、放电侧不重复扣效率。
- 在线规则入口不再只读取单日价格，也不跨日回绕；按完整时间戳查找当前设备小时。
- 在线规则入口会先将电池动作转换为 SOP 并网点目标，拒绝不可表达的动作。
- HA 第三方模式切换后加入 SOP 要求的短暂处理间隔。
- 观测采集器不再默认把无时区设备时间强行解释为 UTC，而是优先从 API 时间戳推导，无法对齐时阻断。

## 3. 尚未完成，不得宣称为正式能力

- 当前 live 入口仍是可解释规则策略，不是已完成的 API-first MILP 正式控制器。
- 当前只完成只读 shadow 和模拟回读测试，没有执行真实 HA 写入和真实比赛控制。
- PV-辐照度校准、负载短期区间和电网-电池-负载损耗参数仍需通过 HA 观测建立。
- 正式控制前还必须完成单站受控写入、下一 tick 回读、功率/SOC/模式一致性核验，再扩展到三站。
- 5 秒是真实轮询周期，不等于可以在每个 5 秒 tick 里观察到 5 秒粒度的新增设备小时数据；时间加速后的设备时间推进必须由 `device_time` 驱动。
