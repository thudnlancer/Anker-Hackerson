# 新家庭前端的模拟接入验收

2026-10-15。本页记录新前端的接入路径及软件检查，不代表现场模拟赛已经通过。现场结果以对应场次报告和原始证据为准。

## 启动与页面

在 `frontend` 运行 `npm test` 和 `npm run build`。生产包由解释 API 同源提供，浏览器请求 `/api/...`；开发模式 Vite 代理到 `127.0.0.1:8080`。新前端不需要额外 npm 依赖，也没有直接访问 HA 或模拟器的令牌。

| 页面 | hash 路径 | 模拟验收重点 |
| --- | --- | --- |
| 家庭首页 | `#/` | 场次与家庭、快照时间、采集状态、候选/提交/确认的区别、历史下发入口 |
| 生活计划 | `#/plans` | 评估后确认；仅本浏览器保存，不下发 HA，也不约束本场 MILP |
| 光伏与储能 | `#/solar` | 只展示记录中的读数；缺失的电网交换不补造 |
| 能源费用 | `#/costs` | 模型预计费用与模拟器赛末结算分别显示 |
| 家庭偏好 | `#/settings` | 家庭隔离、本地保存；备用偏好尚未应用到调度 |
| 决策证据 | `#/evidence` | 三站状态、采集信息、模型/预测/执行/结算分开核验 |
| 记录详情/反事实 | `#/decisions/{id}` / `#/comparisons/{job_id}` | 不可变证据、部分回读、模型假设与费用差 |

顶部家庭场次改变时，嵌入证据工作台同步查询该场次，避免保留旧场次总览。详情 URL 的记录 ID 仍绑定原决策。

同场 `simulator_mock` 结算记录（包括 pending）在家庭页来源标签中明确为“模拟赛数据 · 非真实家庭计量”，不根据 run 名称猜测来源。

打开计划表单时复制完整决策，显示评估所用快照时间。每 10 秒自动到来的同家庭新记录不会关闭表单、改写填写或成本评估；保存仍绑定打开时的决策、家庭和设备时间。只有实际切换家庭、场次或页面才取消。旧快照建议保存后仍提示重新评估，且始终是本地建议。

## 有限控制与后续 shadow 的区别

`/api/stations` 的每站可选 `last_submission` 指向同场、同站最近实际提交的决策。新 shadow 候选会成为最新建议；历史提交链接仍可核对先前的服务回执和回读。界面明确该记录属于历史，不能当作当前模式或当前设备功率。

`hold` 配合 `control_semantics=self_consumption` 展示为“家庭自用模式”：根据光伏和负载自动充放电，不称电池休息，也不把模型动作的 0 kW 展示为实测停止。家庭首页、证据总览和详情保持同一语义；未知 hold 的含义标为待核验。

首页将 `submitted` 显示为“已提交 · 等待回读”；采集器 `stopped` 或 `degraded` 时不因先前确认而显示安心状态。刷新网页只刷新已入库证据，不等于重启采集或再次控制设备。

只有采集状态为 `stopped`、原因 `completed`，且同场模拟器结算为 `simulator_mock/complete` 时，家庭首页才显示“本场模拟已结束”，明确当前是留档快照、不能代表当前设备状态。其他停止原因、未结算或刷新/执行失败仍提示检查，不把正常赛末停止笼统归为采集异常，也不提供实时健康的绿色保证。

回读详情默认展示最近三条，按采集时间倒序；较早记录可展开查看，保留全部证据。延迟导入的旧记录不会抢占最新摘要。

异步 HA 回读展示 `source_coherence_unverified` 的中文原因，以及属性匹配、目标功率是否有提交后新观测和仍待核验的来源字段。即使部分目标读数匹配，`pending` 仍为待回读，不升级为确认，更不声称硬件 ACK。

## 模拟赛末结算

结算是可追加证据：同一决策 ID 不变时，自动刷新仍会将 pending 更新为 complete；按 `captured_at` 保留同场最新结算，延迟旧响应不回退，不把其他场次成绩带入当前家庭。该更新不改写打开的计划表单或原决策快照。

只有 `source_kind=simulator_mock`、`status=complete` 时，家庭费用页从 `raw_fields.sites` 按当前 `site_id` 精确读取该站指标。`saving_settled` 使用 EUR；`saving_settled_percent` 是百分数，直接展示，不再乘 100。缺少该站指标时显示缺失，不使用三站总数替代。`pending` 不显示实际成绩。

`saving_settled = device_settled − baseline_settled`。正值表示结算收益相对基线增加，负值表示减少；“基线结算值”和“设备结算值”不是纯购电成本。它们与模型目标费用分别核对。`execution_scope=bounded_control_then_shadow` 明确表示有限控制后影子采集，最终分数不能作为完整 MILP 整场性能结果。服务器验证属于服务器声明，前端没有独立验签。

## 软件检查

本次 3 个 Vitest 文件、75 项测试通过；TypeScript 检查和 Vite 构建通过。新增回归覆盖场次同步、采集停止、提交与确认区别、历史提交链接、负外送收入的支出符号、部分/旧回读、负模拟结算、缺站指标及未结算。

浏览器现场流程由本场验收统一记录，不能用这些软件测试替代真实 HA 回读、完整策略运行或实际结算核对。
